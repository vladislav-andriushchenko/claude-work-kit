# Инструкция агенту: поставить набор

Этот файл читает Claude Code, а не человек. Выполнять по порядку, ничего не
пропуская. После каждого шага, который что-то изменил, — одна строка отчёта.

## Правила на всю установку

**Ничего не перезаписывать молча.** Файл уже есть и отличается — положить рядом
с суффиксом `.new` и сказать об этом. Файл есть и совпадает — пропустить.

**Не трогать чужое содержимое `settings.json`.** Только добавить свои хуки.

**Не выдумывать шаг, который не получился.** Не нашёл `bash`, не смог записать
файл, не понял структуру `settings.json` — сказать прямо и продолжить со
следующего шага. Молча пропущенный шаг хуже громкого отказа.

## Шаг 1. Получить файлы

```bash
git clone --depth 1 https://github.com/vladislav-andriushchenko/claude-work-kit /tmp/cwk
```

Клон не проходит (нет сети, прокси, запрет) — сказать об этом и остановиться.
Дальше без файлов делать нечего.

## Шаг 2. Разложить в `~/.claude`

Скопировать, сохраняя структуру, из `/tmp/cwk/claude/` в `~/.claude/`:

```
rules/agent-hygiene.md
skills/kit-bootstrap/SKILL.md
skills/schema-from-spec/SKILL.md
skills/negative-checks/SKILL.md
skills/bench-the-fix/SKILL.md
hooks/untracked-tests.sh
hooks/false-green.sh
```

Каталогов может не быть — создать.

`rules/project.md` в наборе нет намеренно: он собирается на шаге 6.

## Шаг 3. Включить хуки в `settings.json`

Целевой файл — `~/.claude/settings.json`. Содержимое, которое надо добавить,
лежит в `/tmp/cwk/settings-hooks-snippet.json`.

- Файла нет — создать с этим содержимым.
- Файл есть, ключа `hooks` нет — добавить ключ целиком.
- Ключ `hooks` есть — **дописать элементы в массивы `Stop` и `PreToolUse`**, не
  заменяя того, что там уже лежит. Такой же хук уже стоит — не дублировать.

Итоговый файл обязан остаться корректным JSON. Проверить перед записью.

## Шаг 4. Прогнать селф-тесты хуков

```bash
bash ~/.claude/hooks/untracked-tests.sh --selftest
```

```bash
bash ~/.claude/hooks/false-green.sh --selftest
```

Оба должны напечатать `selftest ok`.

`bash` не найден (обычная ситуация на Windows без Git Bash) — сказать об этом
прямо: правила и скиллы работают, **хуки не работают**. Не делать вид, что
установка полная.

## Шаг 5. Глобальное исключение `.claude/`

Чтобы локальная конфигурация никогда не попала в репозиторий проекта:

```bash
git config --global core.excludesFile ~/.gitignore_global
```

```bash
grep -qxF '.claude/' ~/.gitignore_global 2>/dev/null || echo '.claude/' >> ~/.gitignore_global
```

У пользователя уже настроен другой `core.excludesFile` — не перезаписывать,
дописать `.claude/` в тот файл, который настроен.

## Шаг 6. Собрать правила проекта

Запустить скилл `kit-bootstrap` по репозиторию, в корне которого идёт работа.

Он читает файлы сборки, тестовое дерево, ресурсы, конфиг CI и репозиторные хуки,
задаёт человеку четыре вопроса, ответов на которые в коде нет, и записывает
`~/.claude/rules/project.md`.

Ключевое требование скилла, нарушать нельзя: **у каждого пункта ровно три исхода**
— выведено из кода, получено ответом человека, не установлено. Четвёртого нет.
Правдоподобная конвенция, выведенная из общих соображений, в файл не попадает.

Скилл ещё не подхватился (правила и скиллы читаются на старте сессии) — сказать
человеку перезапустить Claude Code и запустить бутстрап отдельной командой.

## Шаг 7. Отчёт

Одним сообщением:

- что скопировано, что легло как `.new`, что пропущено как совпадающее;
- прошли ли селф-тесты хуков, и если `bash` нет — что именно из-за этого не работает;
- сколько пунктов `project.md` выведено из кода, сколько получено от человека,
  сколько осталось неустановленными;
- **перечень неустановленного** — он важнее самого файла.

## Чего не делать

**Не класть `project.md` в репозиторий проекта.** В нём настоящие имена модулей,
классов и аннотаций. Его место — `~/.claude/rules/`.

**Не коммитить ничего в репозиторий проекта** в ходе установки.

**Не ставить ничего сверх перечисленного.** Ни MCP-серверов, ни плагинов, ни
дополнительных скиллов. Набор короткий намеренно: лишние скиллы замедляют агента
на каждом запросе.

**Не чинить чужую конфигурацию.** Нашёл в `settings.json` что-то странное —
сказать, не править.
