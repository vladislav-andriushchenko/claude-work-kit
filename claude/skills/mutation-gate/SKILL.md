# Мутационный гейт

Тест, который ни разу не падал, ничего не доказывает. Гейт вносит известную
регрессию в код, прогоняет тесты и читает JUnit XML: мутант «убит», если хотя бы
один тест упал, «выжил», если все зелёные. Вердикт по XML, а не по коду возврата:
с `ignoreFailures = true` Gradle возвращает 0 при красных тестах.

## Порядок

1. Убедиться, что дерево чистое по файлам, которые будут мутироваться (`git status`).
   Гейт восстанавливает файлы сам и сверяет по хэшу, но чужие незакоммиченные правки
   в тех же файлах помешают патчу лечь.
2. Собрать мутации: каталог с файлами `NN-имя.patch`, каждый одна регрессия. Делать
   так: внести правку руками или `sed`, `git diff > mutations/01-имя.patch`,
   `git checkout -- <файл>`. Мутация должна быть той, ради которой тест написан:
   вернуть комбинацию к прежнему набору полей, убрать проверку кода ответа,
   поменять `<` на `<=`. Не «сломать всё подряд».
3. Запустить:

```bash
bash ~/.claude/tools/mutation-gate.sh --mutations mutations --gradle "./gradlew :module:test --tests 'ru.example.SomeTest'"
```

   `--gradle` сужать до модуля и класса: полный прогон домена на каждую мутацию
   стоит минут, а доказывает то же самое. `--results` менять только если XML лежат
   не в `build/test-results`.
4. Прочитать таблицу. `KILLED` с именем упавшего теста, `SURVIVED`, `ERROR`.

## Приёмка

- Код выхода 0 и в таблице у каждого мутанта `KILLED` с именем теста, который
  его поймал. Это и есть артефакт: вставить таблицу в отчёт целиком.
- `SURVIVED` означает, что тест не проверяет то, что заявлено. Чинить тест, не мутацию.
- Код 2 означает, что гейт не смог измерить (baseline красный, тесты не запустились,
  патч не лёг). Это не «выжил» и не «убит», а остановка: сообщить человеку, ничего
  не подставлять.

## Чего не делать

- Не запускать гейт против общих модулей (`core`, `rules`, `build-logic`) без слова
  человека: мутации там ложатся на файлы, которые правит только человек.
- Не заменять гейт словами «мутационно проверено». Нет таблицы, нет проверки.
- Не коммитить каталог `mutations/` в репозиторий проекта без согласования: он
  содержит diff рабочего кода, ему место рядом с задачей, не в main.
